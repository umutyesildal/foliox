## Typography — Geist + Geist Mono

- **Display + body:** Geist (max weights 400 / 500 / 600)
- **Mono (prices, balances, bps, raw/scaled values, timestamps, addresses, tx status):** Geist Mono, always `tabular-nums` for numbers that update in place

Wired via `next/font/google` in `app/app/layout.tsx` (`--font-sans`, `--font-mono`) and `app/tailwind.config.js` (`fontFamily.sans/mono`). Do not swap to naive `<link>` tags.

| Role | Class | Use |

## Gradients (not used)

This palette's mood is minimal/premium and the design audit explicitly bans decorative gradients — none were generated. Surface hierarchy comes from elevation (`--background` → `--card` → `--popover`), 1px borders, and typography.

## Geometry & motion

- 4/8px spacing grid; scale 12/16/24/32.
- Radii: 10px panels, 8px controls, 4px compact chips. True pills only for selected/live states.
- Hierarchy from low-contrast borders + surface shifts, not shadows.
- Motion: `cubic-bezier(0.23, 1, 0.32, 1)`, short property-specific transitions, respect `prefers-reduced-motion`. No `transition-all`.

## Tone and voice

### Words to use

Direct, specific, number-forward, factual. Verbs over adjectives, nouns over metaphors. Sparse and precise — one sentence per idea, lists over paragraphs, numbers over adjectives. Say what an action does, not what it feels like. Use only the compliant product vocabulary: **strategy basket, index basket, onchain equity basket, xStocks-backed strategy token**.

### Words to avoid

- Effort/quality claims: "simply", "just", "easy", "powerful", "seamless", "unlock".
- Hype: "revolutionary", "game-changing", "supercharge", exclamation marks, emojis.
- Premium clichés: "luxury", "exclusive", "elite".
- **Regulatory (hard ban per AGENTS.md §1):** "ETF", "registered fund", "guaranteed", "safe investment", "financial advice", "we manage your money". Anywhere legal/risk language appears, keep the `LEGAL_REVIEW_REQUIRED` placeholder until counsel approves.

### Voice example

> Basket NAV $1,248,350 · share price $1.2483 · drift +40 bps vs target. Redeem is permissionless and oracle-free; outputs are pro-rata, floored to the raw token unit.

## Usage dos and don'ts

**Do:**

- Use the shadcn CSS variables (`bg-background`, `text-foreground`, `bg-primary`, `text-muted-foreground`) everywhere. Never hardcode hex in components.
- Use `font-mono tabular-nums` for any number that updates in place (NAV, balances, bps).
- Show raw vs scaled amounts distinctly (raw = onchain truth, scaled = display) — this is a product requirement, not a style choice.
- Mark data provenance: source + as-of timestamp on every quoted figure. Demo/fixture data must be visibly labeled.
- Test every component in both light and dark mode.

**Don't:**

- Hardcode colors or use decorative gradients, neon glows, faux browser chrome, marquee tickers.
- Use `transition: all` — always property-specific.
- Stack more than one accent hue per screen; status colors are for status only.
- Override shadcn tokens per-component — fix the token in `globals.css` once.
- Present performance as a promise; historical NAV only, never projected APY/yield language.
